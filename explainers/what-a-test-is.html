What a test is

What you are looking at. A test is a small machine that checks one rule of your program. This one is built as a jig on a workbench. A blank (a plain metal slug) marked with a task type is the input: the value you feed in; the card on the front of the shuttle names the one in the machine. The press in the middle, with its name on the head, is the function under test, taskWeight: the piece of code whose behaviour you want to check. It stamps each blank down to a height that stands for the number the function returns, the result. The shuttle then carries the stamped blank to a comparator gauge, which measures it against the number written on the tag beside it, the expected value: the answer you wrote down before running. If the two agree the green lamp lights (the test passes); if not, the red lamp lights and the dial shows by how much (the test fails). (quiz has no rule of its own in the code, so the function gives its default answer, 1.) A bug is a mistake in the code; here it is drawn as a shim slipped into the press, so every part comes out one point too tall.

Try it. Run the three cases one at a time with the buttons under the figure, or press 1, 2 and 3 with the figure focused. Watch the readout at the bottom right. Then switch on Introduce a bug and run a case again: the same test that was green goes red, which is the whole point. A test you have seen fail is the only test you can trust to catch the bug later; that is why Day 3 writes the test first and watches it go red before making it green.
